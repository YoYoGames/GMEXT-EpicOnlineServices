Sessions¶

Epic Online Services Interface: Sessions Interface

The Sessions Interface lets players create, search for, join, and leave online game sessions - the general-purpose matchmaking building block for match-based games. If you need a persistent group of players who stick together across matches, see Lobbies instead.

Note

A session is built/modified through a "session modification" handle: create one with eos_sessions_create_session_modification, configure it with the eos_sessions_session_modification_* setters, then publish it with eos_sessions_update_session.

eos_sessions_create_session_modification¶

Epic Online Services Function: EOS_Sessions_CreateSessionModification

Creates a session modification handle. This handle is used to build up the settings for a brand new session (an empty session_id lets the backend assign one) before calling eos_sessions_update_session to publish it. Configure the modification with the eos_sessions_session_modification_* functions below.

Note

session_id, when provided, must be 16-64 characters. An empty string is invalid; pass an empty string only when you want the backend to assign an id.


Syntax:

eos_sessions_create_session_modification(session_name, session_id, bucket_id, max_players, local_user_id, presence_enabled, sanctions_enabled, allowed_platform_ids)
Argument Type Description
session_name String A local, client-side label for this session. Must be unique among your currently active sessions.
session_id String Backend session id, or an empty string to let the backend assign one.
bucket_id String A logical bucket for filtering search results (e.g. region/gamemode).
max_players Real Maximum number of players allowed in the session.
local_user_id String The Product User ID creating the session.
presence_enabled Boolean Whether this is the user's presence session (only one presence session may exist per local user).
sanctions_enabled Boolean Whether joining players are checked against Sanctions.
allowed_platform_ids Array of Real Platform ids (EOS_EOnlineExternalAccountType-style) allowed to join, or an empty array to allow every platform.


Returns:

Real

A session modification handle (0 on failure), consumed by eos_sessions_update_session or released with eos_sessions_session_modification_release.


Example:

var _mod = eos_sessions_create_session_modification("MySession", "", "region-eu", 4, local_user_id, true, false, []);
eos_sessions_session_modification_set_permission_level(_mod, EOS_ONLINE_SESSION_PERMISSION_LEVEL.PUBLIC_ADVERTISED);
eos_sessions_update_session(_mod, function(_result) {
    show_debug_message($"Session created: {_result.result_code}");
});

eos_sessions_session_modification_release¶

Epic Online Services Function: EOS_SessionModificationHandle_Release

Releases a session modification handle without publishing it. Call this if you decide not to commit changes built up with eos_sessions_create_session_modification.

Note

You do NOT need to call this after eos_sessions_update_session - that function releases the handle internally once it hands the modification off to the SDK.


Syntax:

eos_sessions_session_modification_release(modification_id)
Argument Type Description
modification_id Real A session modification handle.


Returns:

N/A


Example:

eos_sessions_session_modification_release(_mod);

eos_sessions_update_session¶

Epic Online Services Function: EOS_Sessions_UpdateSession

Publishes a session modification, creating the session on the first call or applying changes on later calls. This function consumes and releases modification_id - don't call eos_sessions_session_modification_release on it afterward.

This function operates asynchronously, which means that it does not immediately return the requested result. Instead, upon completion of the task, it will trigger the Callback.


Syntax:

eos_sessions_update_session(modification_id, callback=undefined)
Argument Type Description
modification_id Real A session modification handle from eos_sessions_create_session_modification.
callback Function Called once with the result.


Returns:

N/A


Triggers:

Callback

Fires once with the outcome of the update.

Key Type Description
result EpicSessionsUpdateSessionCallbackInfo


Example:

eos_sessions_update_session(_mod, function(_result) {
    if (_result.result_code == EPIC_RESULT.SUCCESS)
    {
        show_debug_message($"Session '{_result.session_name}' is live ({_result.session_id}).");
    }
});

eos_sessions_register_players¶

Epic Online Services Function: EOS_Sessions_RegisterPlayers

Registers additional players (e.g. local split-screen players, or players who joined outside of the SDK's own join flow) as members of an existing session, so they count toward max_players and can be enumerated via eos_sessions_active_session_get_registered_player_by_index.

This function operates asynchronously, which means that it does not immediately return the requested result. Instead, upon completion of the task, it will trigger the Callback.


Syntax:

eos_sessions_register_players(session_name, target_user_ids, callback=undefined)
Argument Type Description
session_name String The local session name.
target_user_ids Array of String Product User IDs to register.
callback Function Called once with the result.


Returns:

N/A


Triggers:

Callback

Fires once with the registration outcome. If Sanctions checking is enabled on the session, sanctioned players are reported separately and are NOT added to registered_players.

Key Type Description
result EpicSessionsRegisterPlayersCallbackInfo


Example:

eos_sessions_register_players("MySession", [target_user_id], function(_result) {
    show_debug_message($"Registered: {_result.registered_players}, sanctioned: {_result.sanctioned_players}");
});
