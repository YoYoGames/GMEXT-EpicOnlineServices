P2P¶

Epic Online Services Interface: P2P Interface

Send and receive data directly between authenticated users, typically for a multiplayer game's own transport layer. P2P connections are secure by default, using Datagram Transport Layer Security (DTLS).

eos_p2p_send_packet¶

Epic Online Services Function: EOS_P2P_SendPacket

Sends a packet to a peer at the specified socket. If there is already an open connection to this peer, the packet is sent immediately; otherwise a connection attempt is made. A EpicResult.Success result only means the data was accepted to be queued for sending, not that it has been delivered.


Syntax:

eos_p2p_send_packet(local_user_id, remote_user_id, socket_name, channel, data, bytes, allow_delayed_delivery, reliability, disable_auto_accept_connection)
Argument Type Description
local_user_id String The Product User ID of the local user sending this packet.
remote_user_id String The Product User ID of the peer to send the packet to.
socket_name String The socket ID for the data being sent.
channel Real The channel associated with this data.
data Buffer A buffer holding at least bytes bytes to send.
bytes Real The number of bytes from data to send. Must not exceed the buffer's length, and must not exceed EOS_P2P_MAX_PACKET_SIZE.
allow_delayed_delivery Boolean If false and there isn't already an established connection to the peer, this packet is dropped instead of being queued while the connection is negotiated.
reliability EpicPacketReliability The reliability/ordering guarantee for this packet.
disable_auto_accept_connection Boolean If true, this call won't automatically establish a connection with remote_user_id - call eos_p2p_accept_connection first, or the packet is dropped with EpicResult.NoConnection. If false (the default), a connection is opened automatically the first time this is called for a given peer.


Returns:

EpicResult

eos_p2p_receive_packet¶

Epic Online Services Function: EOS_P2P_ReceivePacket

Reads the next queued packet for the local user into out_data, if one exists.

Note

Returns undefined if no packet is available, or if out_data doesn't have enough room (starting at offset) for the packet's bytes.


Syntax:

eos_p2p_receive_packet(local_user_id, out_data, max_bytes, offset, channel)
Argument Type Description
local_user_id String The Product User ID of the user receiving the packet.
out_data Buffer The buffer the packet's bytes are written into.
max_bytes Real The maximum number of bytes to request from the SDK for this call. Pass 0 to use EOS_P2P_MAX_PACKET_SIZE.
offset Real The offset in out_data to start writing at.
channel Real The channel to read from, 0-255. Pass a negative value to read the next packet on any channel.


Returns:

EpicP2PReceivedPacket


Example:

var _size = eos_p2p_get_next_received_packet_size(my_id, -1);
if (_size > 0)
{
    var _buf = buffer_create(_size, buffer_fixed, 1);
    var _packet = eos_p2p_receive_packet(my_id, _buf, _size, 0, -1);
    if (!is_undefined(_packet))
    {
        show_debug_message($"Got {_packet.bytes_written} bytes from {_packet.peer_id}");
    }
    buffer_delete(_buf);
}

eos_p2p_accept_connection¶

Epic Online Services Function: EOS_P2P_AcceptConnection

Accepts or requests a connection with a specific peer on a specific socket ID. If the connection wasn't already locally accepted, EOS securely messages the peer and triggers a eos_p2p_add_notify_peer_connection_request notification for them. If the remote peer accepts, eos_p2p_add_notify_peer_connection_established fires once the connection is ready to send packets. Multiple socket IDs accepted with the same peer share one physical connection.


Syntax:

eos_p2p_accept_connection(local_user_id, remote_user_id, socket_name)
Argument Type Description
local_user_id String The Product User ID of the local user accepting the connection.
remote_user_id String The Product User ID of the remote user.
socket_name String The socket ID of the connection to accept.


Returns:

EpicResult

eos_p2p_close_connection¶

Epic Online Services Function: EOS_P2P_CloseConnection

Stops receiving packets on a specific socket ID with a specific peer, drops any locally queued packets for it, and - if no other socket ID is using the underlying connection with that peer - closes it. If you want to migrate an existing connection to a new socket ID, call eos_p2p_accept_connection with the new socket ID before closing the old one, so the shared physical connection isn't torn down prematurely.

Note

Pass an empty string for socket_name to close every socket with remote_user_id.


Syntax:

eos_p2p_close_connection(local_user_id, remote_user_id, socket_name)
Argument Type Description
local_user_id String The Product User ID of the local user closing the connection.
remote_user_id String The Product User ID of the remote user to disconnect from.
socket_name String The socket ID of the connection to close, or an empty string for all sockets with this peer.


Returns:

EpicResult

eos_p2p_set_relay_control¶

Epic Online Services Function: EOS_P2P_SetRelayControl

Sets how relay servers are used for P2P connections. This only affects new connections, or existing connections that renegotiate (e.g. after a temporary connectivity outage) - it doesn't apply retroactively to already-established connections. Peers with incompatible relay settings won't be able to connect to each other.


Syntax:

eos_p2p_set_relay_control(relay_control)

eos_p2p_set_packet_queue_size¶

Epic Online Services Function: EOS_P2P_SetPacketQueueSize

Sets the maximum size, in bytes, of the incoming and outgoing packet queues. If a queue is shrunk below its current size, already-queued packets are kept, but no new packets can be added until enough are sent or received to make room.

eos_p2p_add_notify_peer_connection_request¶

This function operates asynchronously, which means that it does not immediately return the requested result. Instead, upon completion of the task, it will trigger the Callback.


Syntax:

eos_p2p_add_notify_peer_connection_request(local_user_id, socket_name, callback=undefined)
Argument Type Description
local_user_id String The Product User ID listening for incoming connection requests.
socket_name String The socket ID to filter on, or an empty string to receive requests for every socket.
callback Function Called every time a matching connection request arrives.


Returns:

Real


Triggers:

Callback

Fired every time a matching connection request arrives, for as long as this notification stays registered.

eos_p2p_add_notify_peer_connection_interrupted¶

Epic Online Services Function: EOS_P2P_AddNotifyPeerConnectionInterrupted

Registers to be notified when a previously open or pending connection is interrupted. EOS automatically attempts to reestablish it - a successful reconnect fires eos_p2p_add_notify_peer_connection_established with EpicConnectionEstablishedType.Reconnection; a failed one fires eos_p2p_add_notify_peer_connection_closed instead. Queued packets survive an interruption, but are flushed once the connection actually closes.

Note

Returns 0 if registration failed.

This function operates asynchronously, which means that it does not immediately return the requested result. Instead, upon completion of the task, it will trigger the Callback.


Syntax:

eos_p2p_add_notify_peer_connection_interrupted(local_user_id, socket_name, callback=undefined)
Argument Type Description
local_user_id String The Product User ID listening for this notification.
socket_name String The socket ID to filter on, or an empty string to receive notifications for every socket.
callback Function Called every time a matching connection is interrupted.


Returns:

Real


Triggers:

Callback

Member Description

Moderate You can directly connect to other Moderate and Open peers.

EpicPacketReliability¶

Epic Online Services Enum: EOS_EPacketReliability

Ordered packets are only ordered relative to other ordered packets. Reliable/unreliable and ordered/unordered traffic can share the same socket ID and channel.

These constants are referenced by the following functions:

  • eos_p2p_send_packet


Member Description
UnreliableUnordered Sent once; may arrive out of order or not at all.
ReliableUnordered May be resent; may arrive out of order.
ReliableOrdered May be resent; always arrives in order.

EpicRelayControl¶

Epic Online Services Enum: EOS_ERelayControl

Connections between peers with incompatible relay-control settings may succeed in limited scenarios, but should be treated as unreliable.

These constants are referenced by the following functions:

  • eos_p2p_set_relay_control
  • eos_p2p_get_relay_control


Member Description
NoRelays Never use relay servers. Clients behind restrictive NATs may fail to connect to peers.
AllowRelays Try a direct connection first, fall back to a relay server. Default if not changed.
ForceRelays Always use relay servers. Adds latency to every connection, but hides IP addresses from peers.
