RTC

Epic Online Services Interface: RTC Interface

Real-time voice and peer-to-peer data messaging for a room of participants - typically the members of a Lobbies/Sessions room, though a room can also be joined directly. Covers three related areas: joining/leaving rooms and tracking participants (RTC core), microphone/speaker control (RTC Audio), and a binary data channel alongside the audio (RTC Data).

Note

The extension initialises the RTC interface automatically along with everything else - see Platform.

eos_rtc_join_room

Epic Online Services Function: EOS_RTC_JoinRoom

Joins (or creates, if it doesn't exist yet) an RTC room. A room is a voice/data space shared by every participant who joins it with the same room_name - rooms are commonly created implicitly by eos_lobby_create_lobby/eos_lobby_join_lobby (a Lobby-managed RTC room, see eos_lobby_get_rtc_room_name) or eos_sessions_join_session, but can also be joined directly for a standalone voice/data room.

manual_audio_input/manual_audio_output opt this local user out of the SDK's default capture/playback device handling - set either to true if your game supplies its own microphone capture (via eos_rtc_audio_send_audio) or does its own audio rendering (via the [Callback](https://manual.gamemaker.io/monthly/en/GameMaker_Language/GML_Overview/Method_Variables.htm) on eos_rtc_audio_add_notify_audio_before_render) instead of letting the SDK open the platform's default input/output device.

This function operates asynchronously, which means that it does not immediately return the requested result. Instead, upon completion of the task, it will trigger the Callback.


Syntax:

eos_rtc_join_room(local_user_id, room_name, client_base_url, participant_token, manual_audio_input, manual_audio_output, callback=undefined)
Argument Type Description
local_user_id String The Product User ID of the user joining the room.
room_name String The room to join. Rooms are created on first join.
client_base_url String The RTC room's base URL, normally obtained from a Lobby/Session's
connection details rather than hardcoded.
participant_token String The token authorizing this user to join the room, normally
obtained the same way as client_base_url.
manual_audio_input Boolean true if this game supplies its own captured audio instead of the
SDK's default microphone capture.
manual_audio_output Boolean true if this game renders received audio itself instead of the
SDK's default playback.
callback Function Called once with the result of the join attempt.


Returns:

N/A


Triggers:

Callback

Fires once after the join attempt completes.

Key Type Description
result_code EpicResult EpicResult.Success if the room was joined.
local_user_id String The Product User ID that requested the join.
room_name String The room that was joined.
room_options Array of EpicRTCOption Room-level options reported back by the RTC
backend for this room.


Example:

eos_rtc_join_room(local_user_id, "my_room", client_base_url, participant_token, false, false,
    function(_info)
    {
        if (_info.result_code == EpicResult.Success)
        {
            show_debug_message($"Joined RTC room {_info.room_name}");
        }
    });

eos_rtc_add_notify_disconnected

Epic Online Services Function: EOS_RTC_AddNotifyDisconnected

Registers to be notified when the local user is disconnected from a room. Call eos_rtc_remove_notify_disconnected with the returned ID when you no longer need it.

Note

This always returns an invalid notification ID when used with a Lobby-managed RTC room - use eos_lobby_add_notify_rtc_room_connection_changed instead for those.

This function operates asynchronously, which means that it does not immediately return the requested result. Instead, upon completion of the task, it will trigger the Callback.


Syntax:

eos_rtc_add_notify_disconnected(local_user_id, room_name, callback=undefined)
Argument Type Description
local_user_id String The Product User ID to listen for on this room.
room_name String The room to listen on.
callback Function Called every time the local user is disconnected from the room.


Returns:

Real

A notification ID for use with eos_rtc_remove_notify_disconnected.


Triggers:

Callback

Fires each time the local user is disconnected from the room.

Key Type Description
result_code EpicResult Why the connection ended, e.g. EpicResult.Success (left
cleanly), EpicResult.NoConnection, EpicResult.RTC_USER_KICKED, EpicResult.ServiceFailure.
local_user_id String The Product User ID that was disconnected.
room_name String The room that was disconnected from.

eos_rtc_add_notify_participant_status_changed

Epic Online Services Function: EOS_RTC_AddNotifyParticipantStatusChanged

Registers to be notified when a participant joins or leaves the room, or is added to/removed from an applicable block list. If you register before joining the room, you'll get a notification for every member already present when you join, so you know who's already there.

Note

For a Lobby-managed RTC room, register this during the eos_lobby_create_lobby/ eos_lobby_join_lobby completion callback (once result_code is EpicResult.Success) - registering later can miss notifications for members who joined the room in between.

This function operates asynchronously, which means that it does not immediately return the requested result. Instead, upon completion of the task, it will trigger the Callback.


Syntax:

eos_rtc_add_notify_participant_status_changed(local_user_id, room_name, callback=undefined)
Argument Type Description
local_user_id String The Product User ID to listen for on this room.
room_name String The room to listen on.
callback Function Called every time a participant's status changes.


Returns:

Real

A notification ID for use with eos_rtc_remove_notify_participant_status_changed.


Triggers:

Callback

Fires each time a participant's status changes.

Key Type Description
local_user_id String The Product User ID this notification is registered for.
room_name String The room the participant is in.
participant_id String The Product User ID of the affected participant.
participant_status EpicRTCParticipantStatus Whether the participant joined or left.
participant_in_blocklist Boolean true while the SDK is still resolving whether this
participant is on an applicable block list - a second notification with this set to false follows
once resolved, if they aren't blocked.
participant_metadata Array of EpicRTCParticipantMetadata Metadata attached to the
participant by the RTC backend.

eos_rtc_audio_add_notify_audio_before_send

Epic Online Services Function: EOS_RTCAudio_AddNotifyAudioBeforeSend

Registers to observe the local user's outgoing audio right before it's sent, e.g. for a mic-activity meter or your own recording. The callback only carries metadata (sample rate/channels/frame count and a handle_id) - call eos_rtc_audio_before_send_data_fetch with that handle_id to copy out the actual PCM frames.

Warning

Fetch the data synchronously inside your callback, on the same frame it fires. handle_id is only valid until fetched or until this same registration fires again, whichever happens first - deferring the fetch risks the frames already being gone.

Warning

The underlying EOS SDK documents this hook as a synchronous, in-place modification point - natively, you could edit EOS_RTCAudio_AudioBuffer in place to apply a custom filter/effect before the SDK sends it. This extension's GMFunction callback model always runs your GML on the next frame, so that in-place modification is not achievable through this binding - you can only observe a copy of the frames after the fact, not alter what actually gets sent. If you need real-time audio processing, do it before calling eos_rtc_audio_send_audio in manual-audio-input mode.

Note

This callback can fire from an internal SDK thread, not just the main thread during eos_platform_tick - the same caveat as eos_logging_set_callback (see Logging). Firing the GMFunction itself is still safe from any thread; this only matters if your handler code assumes it's always running in step with your own game logic.

This function operates asynchronously, which means that it does not immediately return the requested result. Instead, upon completion of the task, it will trigger the Callback.
