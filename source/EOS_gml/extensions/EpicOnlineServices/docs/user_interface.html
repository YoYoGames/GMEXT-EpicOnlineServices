User Interface¶

Epic Online Services Interface: UI Interface

The UI Interface controls Epic's built-in social overlay: the Friends list, native platform profile cards, block/report player dialogs, and controller-driven overlay navigation.

Any callback/notification elsewhere in this extension that hands you a ui_event_id must be acknowledged via eos_ui_acknowledge_event_id - see that function's description.

These functions are provided for controlling the social overlay:

  • eos_ui_show_friends

eos_ui_show_friends¶

Epic Online Services Function: EOS_UI_ShowFriends

Shows the Friends overlay for the given local user. On desktop platforms this is a fully featured friends list; on mobile it's a slimmed-down view.

Note

On some platforms the user must be logged in to Epic Account Services (see Auth) for this call to have an effect.

This function operates asynchronously, which means that it does not immediately return the requested result. Instead, upon completion of the task, it will trigger the Callback.


Syntax:

eos_ui_show_friends(local_user_id, callback=undefined)
Argument Type Description
local_user_id String The Product User ID of the local player requesting the overlay.
callback Function Called once the overlay has been shown (or the request has failed).


Returns:

N/A


Triggers:

Callback

Fires once, with the result of the show-friends request.

Key Type Description
result EpicUIShowFriendsCallbackInfo


Example:

eos_ui_show_friends(local_user_id, function(_result)
{
    if (_result.result_code == EpicResult.Success)
    {
        show_debug_message("Friends overlay shown.");
    }
});
The above code shows the Friends overlay to the given local user and logs once it's up.

eos_ui_acknowledge_event_id¶

Epic Online Services Function: EOS_UI_AcknowledgeEventId

Acknowledges a UI event raised by the social overlay (e.g. a join-game or native-invite request that came in with a ui_event_id).

Whenever a callback/notification hands you a ui_event_id (join-game-accepted, native-invite-requested, and similar overlay-driven events across Sessions/Lobbies/Custom Invites), you MUST call this function with that ID once you're done handling it, passing the real outcome as result_code. Skipping this - or acknowledging with a hardcoded EpicResult instead of the actual outcome - leaves the social overlay UI hanging or reports a false result to Epic's backend.


Syntax:

eos_ui_acknowledge_event_id(ui_event_id, result_code)
Argument Type Description
ui_event_id Real The ID of the UI event to acknowledge, taken from the triggering callback/notification struct.
result_code EpicResult The real outcome of handling the event (e.g. EpicResult.Success once a join has actually completed, or an error code if it failed).


Returns:

EpicResult

eos_ui_report_input_state¶

Epic Online Services Function: EOS_UI_ReportInputState

Reports the current state of a fixed set of gamepad-style buttons to the SDK so the social overlay can be driven with a controller instead of a mouse/keyboard. Call this every frame the overlay is visible (e.g. from the Step event) with the current button states.

Note

This only reports the 4 D-Pad directions plus an accept/cancel pair - it is not a full input passthrough. Mouse and analog-stick state are not exposed by this function.


Syntax:

eos_ui_report_input_state(button_down, button_up, button_left, button_right, button_accept, button_cancel)
Argument Type Description
button_down Boolean true while the D-Pad down button is held.
button_up Boolean true while the D-Pad up button is held.
button_left Boolean true while the D-Pad left button is held.
button_right Boolean true while the D-Pad right button is held.
button_accept Boolean true while the accept/confirm face button is held.
button_cancel Boolean true while the cancel/back face button is held.


Returns:

N/A


Example:

/// Step Event
eos_ui_report_input_state(
    keyboard_check(vk_down), keyboard_check(vk_up),
    keyboard_check(vk_left), keyboard_check(vk_right),
    keyboard_check(vk_enter), keyboard_check(vk_escape)
);
The above code drives the overlay's D-Pad/accept/cancel input from the keyboard every step.

eos_ui_add_notify_display_settings_updated¶

Epic Online Services Function: EOS_UI_AddNotifyDisplaySettingsUpdated

Registers to receive a notification whenever the visibility or input-exclusivity of the overlay changes (e.g. the player opens/closes the Friends overlay, or the overlay starts/stops capturing exclusive input). If the returned notification ID is valid, call eos_ui_remove_notify_display_settings_updated when you no longer need it.

This function operates asynchronously, which means that it does not immediately return the requested result. Instead, upon completion of the task, it will trigger the Callback.


Syntax:

eos_ui_add_notify_display_settings_updated(callback=undefined)
Argument Type Description
callback Function Called every time the overlay's display settings change.


Returns:

Real

A notification ID, or 0 if registration failed.


Triggers:

Callback

Fires every time the overlay's visibility or input-exclusivity changes.

Key Type Description
result EpicUIDisplaySettingsUpdatedCallbackInfo
